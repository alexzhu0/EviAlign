# Business Sandbox Comprehensive Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the business sandbox into a reproducible test environment with explicit acceptance gates, repaired model-loop defects, fresh model validation, and a durable feedback ledger.

**Architecture:** Keep AgentHarness as the pre-execution evidence producer and keep all execution authority in the independent synthetic sandbox. Make behavior changes in the isolated `/tmp/agentharness-business-sandbox` copy with test-first red/green evidence, then copy explicit files into the external runtime. Preserve prior failed reports and use a new frozen model suite after prompt or loop changes.

**Tech Stack:** Python 3 standard library, SQLite in memory, `unittest`, local HTTP server, DeepSeek `deepseek-v4-pro`, AgentHarness CLI.

**Spec:** `docs/superpowers/specs/2026-09-15-business-sandbox-design.md`

## Global Constraints

- AgentHarness evidence is pre-execution evidence and always reports `result_status: not_executed`.
- The sandbox runtime independently authenticates, authorizes, validates, and executes synthetic actions.
- All data is synthetic and in memory; no real payment, email, external database, arbitrary SQL, or shell tool is available.
- Unknown tool arguments remain fail-closed; model fixes cannot weaken the runtime whitelist.
- Existing model holdout reports remain immutable historical evidence and cannot be rescored as unseen tests.
- Use explicit file copies only; do not stage or commit unrelated AgentHarness work.
